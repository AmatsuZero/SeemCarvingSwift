项目地图

按能力划分的架构

算法留在可移植的 Core；可选计算与宿主图像 adapter 只向内依赖，Core 永不反向依赖它们。

依赖图

SeamCarvingCore
├── SeamCarvingAccelerate
├── SeamCarvingMetal
├── SeamCarvingAppleRuntime       (Core + Accelerate + Metal)
├── SeamCarvingAppleImaging       (Runtime + CGImage/CIImage/Core Image)
├── SeamCarvingCoreVideo          (Runtime + CVPixelBuffer)
├── SeamCarvingUIKit              (Runtime + Imaging + UIImage)
└── SeamCarvingAppKit             (Runtime + Imaging + NSImage)

SeamCarvingApple = Runtime + Imaging 的兼容 re-export
SeamCarvingVision = Core + Runtime + Imaging + Vision
SeamCarvingCLI = Core + Runtime + Imaging + Vision

模块职责

Product职责
SeamCarvingCoreRGBA8 像素、mask、seam 算法、CPU backend 与通用配置。
SeamCarvingAppleRuntimeMetal → Accelerate → CPU 的 Apple backend 选择，提供 RGBA8 API。
SeamCarvingAppleImagingCGImage/CIImage bridge 与 Core Image Lanczos pre-scale。
SeamCarvingCoreVideoCVPixelBuffer bridge。
SeamCarvingUIKitUIImage bridge、orientation 与 scale。
SeamCarvingAppKitNSImage raster bridge。
SeamCarvingApple只为 Runtime + Imaging 提供 v2 兼容 facade。

边界规则

Core 不导入 Apple 图形、媒体或计算 framework，也不含平台条件编译。Runtime 只做 backend capability 选择，不出现图像类型。UIKit/AppKit 分属不同 target；为了让 SwiftPM 在不兼容 host 上发现 target，每个 target 只允许一个 whole-file 自身 framework compile guard，不能混入另一 UI framework 或 Catalyst 行为分支。

未来平台

Wasm、Android、Windows adapter 应把宿主 buffer 转为 RGBA8Image，并只依赖 Core（以及明确需要的 runtime）。它们尚未是已实现 product；Core CI matrix 是跨 host 可移植性的验证 gate。
