SwiftUI app guide

The app is one SeamCarvingApp target with shared SwiftUI sources. It adapts from a compact navigation stack on iPhone to a sidebar/detail layout on iPad and Mac Catalyst.

Build and run

The Xcode project is generated from Apps/SeamCarvingApp/project.yml. The generated project is ignored by Git, so regenerate it after changing the YAML.

cd Apps/SeamCarvingApp
xcodegen generate
xcodebuild -project SeamCarvingApp.xcodeproj -scheme SeamCarvingApp \
  -destination 'generic/platform=iOS' build
xcodebuild -project SeamCarvingApp.xcodeproj -scheme SeamCarvingApp \
  -destination 'platform=macOS,variant=Mac Catalyst' \
  CODE_SIGNING_ALLOWED=NO build

For a physical device, select your Apple Development Team for the app, unit-test, and UI-test targets. A personal team may require Xcode to create a provisioning profile for each test bundle.

Normal workflow

  1. Import. On iPhone, iPad, and Catalyst, choose Photos or Files…. The model decodes the image into canonical RGBA8 pixels.
  2. Set the target. Edit Target width and Target height; enable Lock aspect ratio when both fields should track each other.
  3. Choose the algorithm. Select Backward Sobel or Forward Luma, then Width then Height, Height then Width, or Adaptive.
  4. Choose the backend. Automatic tries Metal, Accelerate, then CPU. Deterministic uses the reproducible CPU behavior. None keeps exact seam semantics; Lanczos + exact residual is the explicit Apple-only approximation.
  5. Paint masks. Use Protect, Remove, or Erase; adjust Brush size and Strength. Use Undo, Redo, Clear masks, or Reset masks as needed.
  6. Protect faces. Enable Face protection, choose Caire-inspired or Vision quality, choose Detect once or Re-detect each pass, adjust confidence/expansion, and optionally exclude detected regions.
  7. Resize and export. Press Resize; an active operation exposes cancellation and progress. Choose PNG or JPEG, then press Export image and use the platform share sheet/file destination.

Platform behavior

PlatformLayout and inputNotes
iPhoneCompact navigation stack; canvas and controls scroll vertically.Photos and Files import use the iOS APIs.
iPadRegular navigation split view with sidebar controls and detail canvas; all interface orientations are declared.Simulator UI automation is the reliable UI-test environment.
Mac CatalystThe same iOS target runs with a regular sidebar/detail layout.Use a valid Apple Development identity for signed runs; there is no separate native AppKit target.

Shared controls use explicit disabled-state colors so dark mode keeps Export image and Resize readable. The Mac Catalyst app may still print benign macOS/Xcode service diagnostics such as LaunchServices or ViewBridge messages when launched from Xcode.

Testing status and limits

The acceptance record is maintained in the capability matrix.

  • iPhone/iPad Simulator: 31 unit tests and 2 UI tests pass in the recorded regression.
  • Mac Catalyst: clean build and 31 unit tests pass; signed Catalyst UI-runner availability depends on the local Mac Development identity.
  • Physical iPad: app/test host signing, install, and 31 unit tests pass with the personal development profile.
  • Physical iPad UI XCTest: the runner times out while enabling automation mode before any UI test method runs. This is recorded as a device/XCTest service limitation, not a passing UI test.
  • Metal: package parity tests and a previous signed 16/16 physical screening exist. A fresh release benchmark needs a dedicated signed Metal test host.

Troubleshooting

  • Project missing: run xcodegen generate from this directory.
  • Signing failure: configure the same Team and automatic signing for the app, unit-test, and UI-test targets. Do not commit local provisioning settings.
  • Import failure: confirm the selected file is an image and grant Photos/Files access.
  • UI automation timeout on iPad: restart Xcode/device, use USB and an unlocked device, retry the UI target alone, and use the iPad Simulator for automated UI acceptance when the physical runner still cannot enable automation.
  • Console noise: LSPrefs, FSFindFolder, ViewBridge, task-port, and similar messages are macOS/Xcode diagnostics when the app otherwise runs; adding dangerous entitlements is not a fix.
