Seam carving 原理

Seam 是一条每行或每列恰好经过一个像素的连通路径。删除或插入低能量 seam，可以改变尺寸并尽量保留视觉重要结构。

以下是原创示意图，不复制论文配图；它们解释 SeamCarvingCore 的语义，颜色用于表达关系而非真实像素值。

3. 保护/移除 mask 如何改变能量

说明：mask 不会直接画出 seam，而是改变 seam 选择使用的能量。hard protect 的代价为无穷，并在重叠时覆盖 remove。

4. Backward 与 Forward 能量

说明：Backward energy 问“当前边缘有多强”，Forward energy 问“这次编辑会让新的邻居产生多大断裂”；两者进入同一 seam 选择循环。

源码模块：BackwardEnergy / ForwardEnergy · EnergyMode

5. 累计代价与 seam 回溯

说明：每个格子保存到达它的最小累计代价和前驱选择；从底行最小格回溯即可恢复一条连通 seam。

源码模块：DynamicProgramming · SeamPath

6. 缩小与放大都是重复的 seam 编辑

删除的 seam插入的 seam显著主体保持明确

说明：缩小删除低能量 seam（W → W − 1），放大插入选定 seam（W → W + 1）；重复直到达到目标尺寸。

源码模块：ResizePlanner / SeamEditor · ResizeOptions

论文参考：核心思想可参考 Avidan 与 Shamir 的论文《Seam Carving for Content-Aware Image Resizing》（ACM TOG 2007，DOI）；本文示意图为原创示意，不复制论文配图。

编辑循环

  1. 计算亮度和能量。 Backward Sobel 使用 clamp-to-edge 的 3×3 梯度，能量是 abs(gx) + abs(gy)；Forward luma 估计删除后相邻像素重新连接产生的代价。
  2. 动态规划。 对每行/列累积最小前驱成本；相同成本选择最小前驱 x，保证参考结果稳定。
  3. 选择 seam。 从最小终点回溯，生成包含方向、坐标和总成本的 SeamPath。
  4. 应用 mask。 hard protect 贡献无穷成本，soft protect 增加加权成本，remove 减少加权成本；保护与移除重叠时保护优先。
  5. 编辑图像和 mask。 删除或插入一条 seam，并同步所有 mask。
  6. 进度与取消。 每次提交后回调 ResizeProgress，在编辑之间检查 Task cancellation；seam observer 抛错会在应用该 seam 前停止。

尺寸顺序和能量

.widthThenHeight 先处理垂直 seam，.heightThenWidth 相反，.adaptiveNormalizedCost 每次比较归一化成本。Backward Sobel 先将 sRGB 解码到线性光，再用 BT.709 系数 0.2126R + 0.7152G + 0.0722B 计算 luma；blur 和 Sobel threshold 只作用于该模式。Forward luma 考虑编辑后像素连接的 discontinuity。

Protect、Remove 和对象移除

Mask 是值域为 0...1 的 row-major Float 平面。多个保护层可以是 hard 或 soft；remove mask 让 seam 更愿意穿过标记区域。专用 removeObject 工作流会持续选择穿过目标的 seam，并可在完成后恢复原始尺寸。

放大与 residual 预缩放

Seam insertion 可以放大宽或高。默认 .none 不隐式 Lanczos，保持精确的逐 seam 语义。显式的 Apple-only .lanczosThenExactResidual 会先用 Core Image 同步缩放图像和所有 mask，再用 seam carving 达到精确目标；这是可选近似。

人脸保护

SeamCarvingVision 将 Vision 人脸矩形变成 Core protection mask。.caireInspired 默认 expansion 0.10，.visionQuality 默认 expansion 0.20、feather 0.30；两者都支持 protection weight 和 minimum confidence。.detectOnceAndTransformMask 只检测一次并变换 mask；.redetectEveryPass 每个删除 pass 重新检测，目前不支持放大。

这里是 Caire-inspired 的保护策略，不是 Caire 或 Pigo detector 兼容；实际 detector 是 Apple Vision。

后端策略

Preference行为
.cpu参考实现，适合复现和 debug seam observer。
.accelerateApple Accelerate 实现，并通过 parity 测试对齐 Core。
.metal可选 GPU 路径；支持的 shrink 会加速，横向编辑使用 CPU transpose，放大和 adaptive order 使用 CPU 参考路径。
.automatic依次尝试 Metal、Accelerate、CPU；deterministic 会选择 CPU。

CLI 开启 --debug 时会强制 CPU，因为 seam observation 是 CPU artifact 路径。Metal 可用性和性能依设备与工具链而变。

限制与非目标

  • 不支持视频 temporal coherence、learned saliency、transport maps、MLX、Core ML。
  • canonical RGBA8 路径不支持 HDR/extended-range。
  • Vision 是可选 Apple adapter，Core 不依赖 Vision。
  • Face redetection cadence 不支持放大。
  • Metal 不承诺每个操作都在 GPU 执行，CPU fallback 是设计的一部分。
