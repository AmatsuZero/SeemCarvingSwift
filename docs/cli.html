Command line

seamcarve-cli

A macOS executable for content-aware image resizing. The command uses Swift Argument Parser for argv syntax and keeps image processing, batch orchestration, and exit-code behavior in the SeamCarvingCLI module.

Build and inspect help

swift build --product seamcarve-cli
swift run seamcarve-cli --help

The executable is currently guarded for macOS because it uses Core Graphics, ImageIO, and URLSession image I/O. The authoritative option spelling is the output of --help and Sources/SeamCarvingCLI/CLIArgumentParser.swift.

Invocation forms

# Exact dimensions
seamcarve-cli INPUT OUTPUT --width PIXELS --height PIXELS

# Percentage or square mode
seamcarve-cli INPUT OUTPUT --percentage PERCENT
seamcarve-cli INPUT OUTPUT --square

# Batch mode (do not provide positional INPUT/OUTPUT)
seamcarve-cli --input-dir INPUT_DIR --output-dir OUTPUT_DIR \
  --width PIXELS --height PIXELS

INPUT may be a local path, an explicit http(s) URL, or - for binary stdin. OUTPUT may be a local path or - for binary stdout. Exactly one resize mode is required: width plus height, percentage, or square.

Resize and backend options

OptionAccepted values / behavior
--width, --heightPositive exact target dimensions; both are required together.
--percentage PPositive source-relative percentage; values above 100 enlarge, values below 100 shrink, and each axis rounds to at least 1.
--squareUses the source short edge for both dimensions.
--backendautomatic (default), cpu, accelerate, or metal.
--energybackward (default) or forward.
--orderwidth-first (default), height-first, or adaptive.
--pre-scalenone (default) or lanczos-residual; the latter is the explicit Apple-only approximation.
--deterministicUse deterministic backend behavior where supported; the Apple facade chooses CPU.
--blur-radiusNon-negative backward-Sobel luma blur radius.
--sobel-thresholdNon-negative backward-Sobel gradient threshold.

Blur radius and Sobel threshold cannot be combined with --energy forward. If --debug is enabled with --backend metal or automatic, seam observation forces the effective backend to CPU and writes a warning to stderr.

Masks and face protection

seamcarve-cli input.png output.png --width 900 --height 600 \
  --protect-mask subject-mask.png --protect-strength hard

seamcarve-cli input.png output.png --width 900 --height 600 \
  --remove-mask object-mask.png --removal-weight 1500

seamcarve-cli portrait.jpg portrait-resized.jpg --percentage 80 \
  --face-policy caire --face-cadence once

seamcarve-cli portrait.jpg portrait-resized.jpg --percentage 80 \
  --face-policy vision --face-cadence each-pass
  • --protect-mask and --remove-mask read local image files and require dimensions identical to the input.
  • Mask intensity is the maximum of the decoded red, green, and blue channels, normalized to 0...1.
  • --protect-strength hard makes marked protection pixels unavailable; soft uses --protect-weight (default 1000).
  • --removal-weight defaults to 1000 and makes marked removal pixels attractive to cross.
  • --face-policy caire or vision selects the corresponding Vision policy defaults. --face-cadence once is the default; each-pass redetects for each pass.

Batch mode deliberately does not accept single-file mask arguments. Use a separate invocation when every file needs a different mask.

Output formats and streams

# Format inferred from output extension
seamcarve-cli input.png output.jpg --width 800 --height 600

# Explicit format overrides the extension
seamcarve-cli input.png result.data --width 800 --height 600 --format bmp

# Binary pipeline; stdout contains only image bytes
cat input.png | seamcarve-cli - - --width 800 --height 600 --format png > result.png

Supported explicit formats are png, jpeg/jpg, and bmp. With a local output path, the normal summary is printed to stdout as WIDTHxHEIGHT BACKEND; progress and errors are on stderr. With output -, stdout is reserved for image bytes and the summary is suppressed.

Debug seam artifacts

seamcarve-cli input.png debug-output.png --width 800 --height 600 \
  --debug --debug-directory debug-seams \
  --seam-color '#ff0066cc' --seam-shape line

--debug requires --debug-directory. The directory receives a manifest.json and one PNG overlay per observed seam. Coordinates use the current image before the edit and a top-left origin. --seam-shape is line or points and --seam-color accepts RRGGBB, RRGGBBAA, or an optional leading #.

Batch processing

# Direct children only; unsupported files are skipped
seamcarve-cli --input-dir photos --output-dir resized \
  --percentage 80 --concurrency 4

# Preserve relative subdirectories and recurse
seamcarve-cli --input-dir photos --output-dir resized \
  --width 1200 --height 800 --recursive --concurrency 2

Batch input and output must be local directories. Supported input extensions are PNG, JPG/JPEG, and BMP. Jobs are sorted by normalized relative path and run with a bounded concurrency limit (default 2). The output keeps the relative path; an explicit --format changes each file's extension to .png, .jpg, or .bmp. Existing subdirectories are created as needed.

Each successful job is logged as processed path -> WxH backend. Individual failures are logged and included in the final summary; the process exits with data-error status if any job fails. Batch mode does not support debug artifacts or single-file masks.

Exit codes and troubleshooting

CodeNameTypical cause
0successResize and output completed.
64usageInvalid or conflicting arguments, missing resize mode, reserved/incompatible configuration, or invalid debug combination.
65data errorInput/mask cannot be decoded, mask dimensions differ, output format is unsupported, or output cannot be written. A batch with failed jobs also uses this status.
70software errorUnexpected processing failure.
130cancelledCancellation, conventionally 128 + SIGINT.

Read diagnostics from stderr. For a stream pipeline, never merge stderr into stdout because stdout may contain encoded image bytes.
