How it works

Seam-carving principles

A seam is a connected path of one pixel per row or column. Removing low-energy seams changes image dimensions while attempting to preserve visually important structure.

Original reference: the core idea is described in Avidan and Shamir, “Seam Carving for Content-Aware Image Resizing”, ACM Transactions on Graphics (2007), DOI 10.1145/1276377.1276390. The diagrams above are newly authored explanatory schematics and do not reproduce the paper’s figures.

The edit loop

  1. Build luma and energy. Backward Sobel uses clamp-to-edge 3×3 gradients with abs(gx) + abs(gy). Forward luma evaluates the cost introduced by joining neighboring pixels after an edit.
  2. Run dynamic programming. For each row/column, accumulate the cheapest predecessor cost. Ties choose the smallest predecessor x so the reference result is deterministic.
  3. Select a seam. Trace the minimum-cost endpoint backward to construct a SeamPath with orientation, coordinates, and total cost.
  4. Apply mask adjustments. Hard protection contributes infinite cost, soft protection adds a weighted cost, and removal subtracts a weighted cost. Hard protection wins when protection and removal overlap.
  5. Edit the image and masks. Remove or insert one seam, preserving mask alignment. For a normal resize, repeat until the target width/height is reached.
  6. Report or cancel. Emit ResizeProgress after a committed edit and check task cancellation between edits. A seam observer can stop the operation before the observed seam is applied.

Dimension order

.widthThenHeight removes/inserts vertical seams before horizontal seams. .heightThenWidth reverses that order. .adaptiveNormalizedCost compares the normalized cost of the available vertical and horizontal seams at each decision. The CLI spells these as width-first, height-first, and adaptive; the app labels them “Width then Height”, “Height then Width”, and “Adaptive”.

Energy and masks

Backward Sobel

Input bytes are decoded from sRGB to linear light before BT.709 luma is computed with 0.2126R + 0.7152G + 0.0722B. Optional box blur and Sobel threshold controls apply only to this energy mode.

Forward luma

Forward luma accounts for the neighboring-pixel discontinuity created by joining pixels after a seam is removed. It is useful when the cost of the edit itself matters more than only the current gradient.

Protect and remove

Each Mask stores values in 0...1. Multiple protection layers can be hard or soft. A removal mask makes marked pixels attractive to cross. The dedicated removeObject workflow keeps selecting seams that cross the removal mask and can resize back to the original dimensions afterward.

Enlargement and residual pre-scaling

Seam insertion can enlarge either dimension. The default PreScaleStrategy.none performs exact sequential seam operations without an implicit resize. The explicit Apple-only .lanczosThenExactResidual strategy first uses Core Image to pre-scale the image and every mask, then uses exact residual seam carving to reach the requested target. This is an opt-in approximation, not a replacement for exact semantics.

Face protection

SeamCarvingVision turns Vision face rectangles into ordinary Core protection masks. The .caireInspired policy uses a default 0.10 expansion fraction; .visionQuality uses a default 0.20 expansion and 0.30 feather fraction. Both have a protection weight and minimum confidence. .detectOnceAndTransformMask detects once and transforms the generated mask; .redetectEveryPass detects again for each pass and currently supports seam removal only, not enlargement.

This is a Caire-inspired protection policy, not compatibility with Caire or its face detector. The actual detector is Apple Vision and remains optional.

Backend policy

PreferenceBehavior
.cpuReference implementation; useful for reproducible results and debug seam observations.
.accelerateApple Accelerate implementation with parity tests against Core.
.metalOptional GPU path. It accelerates supported shrink work; horizontal edits use CPU transposition, while enlargement and adaptive ordering intentionally use the CPU reference path to preserve semantics.
.automaticTry Metal, then Accelerate, then CPU. deterministic: true selects CPU behavior.

The CLI forces CPU when --debug is enabled because seam observation is a CPU-only artifact path. Metal availability and performance are device/toolchain dependent; package parity is not a promise of equal timing.

Limitations and non-goals

  • No temporal coherence for video, learned saliency, transport maps, MLX, or Core ML.
  • No HDR or extended-range input in the canonical RGBA8 path.
  • Vision is an optional Apple adapter; Core remains platform independent.
  • Face redetection cadence does not support enlargement.
  • Metal does not make every operation GPU-only; CPU fallback is intentional.
